# Spec：PDF 四类元素 × 三个库 提取矩阵讲义（HTML）

> 文档性质：本 spec 定义 `docs/pdf-element-matrix.html` 的结构、内容来源与验收标准。
> 生成器：`scripts/build_matrix_html.py`（读取 spec 中定义的数据来源，产出 HTML）。

## 1. 目标

用一张 **4 列 × 4 行**的矩阵表，回答一个问题：
"PDF 里的 **文字 / 图片 / 表格 / 表单** 四类元素，
**（a）在 PDF 底层是什么原码、用阅读器打开长什么样**；
**（b）PyMuPDF / Unstructured / LlamaParse 分别是**怎么提取的、原理是什么、提取出来的结果是什么样子**？"

## 2. 表格结构

```
         | 文字                    | 图片                    | 表格                    | 表单
---------+-------------------------+-------------------------+-------------------------+-------------------------
PDF 原样 | PDF 原码 + 渲染效果图   | PDF 原码 + 渲染效果图    | PDF 原码 + 渲染效果图    | PDF 原码 + 渲染效果图
---------+-------------------------+-------------------------+-------------------------+-------------------------
PyMuPDF  | 怎么提取 / 原理 / 结果  | 同左                    | 同左                    | 同左
---------+-------------------------+-------------------------+-------------------------+-------------------------
Unstructured | 同左                | 同左                    | 同左                    | 同左
---------+-------------------------+-------------------------+-------------------------+-------------------------
LlamaParse  | 同左                | 同左                    | 同左                    | 同左
```

- 列 = 元素类型；行 = "PDF 本身" + 三个库。
- 元素类型确定列色：文字=蓝，图片=绿，表格=橙，表单=紫（贯穿表头、原码、结果）。

## 3. 分析对象与页面区域

对象：`data/generated/sample_mixed_all.pdf`（`scripts/make_sample_pdfs.py` 生成，一页 595×842pt，
含五类内容：标题/正文/中文/列表、合成位图、5×4 网格表、6 个 AcroForm 控件）。

页面区域（PyMuPDF 坐标，原点左上、y 向下，按页面内容实测标定）：

| 元素 | 区域 rect | 包含内容 |
|---|---|---|
| 文字 | (40, 40, 500, 350)  | 标题、引言、正文、中文段、4 条列表 |
| 图片 | (40, 352, 310, 555) | 合成柱状图 + 题注 Figure 1 |
| 表格 | (315, 352, 585, 555)| 5×4 表格 + 题注 Table 1 |
| 表单 | (40, 560, 585, 842) | Section 2 标题 + 6 个控件及标签 |

## 4. 每格内容定义

### 4.1 行 1「PDF 原样」（每个元素类型一格）：

- **PDF 原码**：该区域内元素对应的底层代码原文（`pre` 展示，滚动）：
  - 文字：内容流片段（`Tm/Tf/TJ` 组），展示代表行；附注实际行数与"原码里没有标题/列表标记"
  - 图片：内容流两行（`cm` + `/fzImg0 Do`）+ 图片对象字典（`/Type /XObject /Subtype /Image ...`）
  - 表格：网格线片段（`re/w/h/RG/S` 组）+ 一句注释（"表格 = 20 个矩形 + 20 条文字，无表格对象"）
  - 表单：**不在内容流**——展示 Widget 注解对象字典原文（`/FT /T /V /Rect /AP ...`）
- **渲染效果**：`page.get_pixmap(clip=区域, dpi=150)` → PNG → base64 内嵌为 `<img>`，
  模拟"用阅读器/浏览器打开"看到的样式（真实渲染，非示意图）。

### 4.2 行 2-4（三个库 × 每类元素一格）：

每格三段式：
1. **怎么提取**：一句说明 + 实际 API 调用代码片段（`code`）；
2. **原理**：一句话（关键机制；解释为什么能/不能）；
3. **提取结果**：真实运行输出节选（`pre`）。

### 4.3 各库各元素的"结果"来源（真实，不许编造）

| 库 | 文字 | 图片 | 表格 | 表单 |
|---|---|---|---|---|
| PyMuPDF | `get_text("blocks")` 按区域过滤（bbox+文本） | `get_images` + `get_image_rects`（尺寸/位置） | `find_tables().tables[0].extract()` 5×4 行列 | `page.widgets()` 字段名/类型/值清单 |
| Unstructured | `partition_pdf(strategy="fast")`，按元素 bbox 与区域求交过滤（Title/NarrativeText/ListItem） | 同法过滤：多数为空 + 只有题注 → 结论"fast 无 Image 元素" | 同法过滤：单元格文字散落为独立元素（含错判），结论"无 Table 元素" | 同法过滤：标签文字（Title/Footer）→ 结论"拿不到控件" |
| LlamaParse | 无 key：API 用法 + 预期输出示意（标注"预期"，因云端需 key） | 同左（`get_images`） | 同左（Markdown 表格还原示意） | 同左（文字重建视图） |

## 5. 页面设计

- 单文件 HTML+CSS，**无外部依赖**、离线可开；`min-width: 1200px` + 横向滚动；深色代码区 / 浅色正文区。
- 顶部：简短说明 + 图例（行/列含义、四种颜色）；底部：复现命令。
- 表头行（第 1 行）+ 左列（行标签）固定配色；每个单元格内部小标题：`怎么提取` `原理` `提取结果`。
- LlamaParse 格内加"⚠️ 预期输出"标记。

## 6. 验收标准

1. 表格为 4 列 × 4 行（+1 行表头），无缺格；
2. 行 1 每格有真实渲染图（base64 PNG）与真实 PDF 原码；
3. 行 2-4 每格含三段式；"提取结果"必须是脚本真实运行产物（PyMuPDF/Unstructured 现场采集，LlamaParse 标注"预期"）；
4. HTML 无未替换占位符；无密钥；无外部 CDN 依赖；
5. 重新运行生成器可得到相同结构的产物（数据确定性：样例由确定性脚本生成）。

## 7. 生成命令

```bash
.venv/bin/python scripts/make_sample_pdfs.py     # 若 PDF 被改动，先重新生成
.venv/bin/python scripts/build_matrix_html.py    # → docs/pdf-element-matrix.html
```
